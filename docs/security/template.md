# NN. Title in Title Case

- **Status:** Draft | Accepted | Deprecated
- **Date:** YYYY-MM-DD
- **Deciders:** GitHub handles of people who reviewed the security assessment
- **Researcher:** security specialist or designated reviewer
- **Purpose:** What security concern this document addresses
- **Feeds into:** related ADRs, mechanism docs, or governance policies it references
- **Authors:** @Githab-capibara

## Context

What threat, vulnerability, or defensive requirement is this document establishing?
Why does it matter to operators, contributors, or auditors? Two or three short
paragraphs. Link to prior security decisions rather than restating them.

## Assessment

The body of the security document — threat analysis, attack surface mapping,
mitigation strategies, or audit findings. Keep sections short and scannable; use
tables and numbered lists where appropriate.

## Mitigation

What controls, checks, or procedural changes address the finding? Be concrete
about what is implemented, what is planned, and what is out of scope.

## References

- Links to related ADRs, mechanism docs, or other security documents
- External advisories, CVEs, or standards this document aligns with
- Tooling used for analysis (e.g. Semgrep rules, dependency audit results)
